# Licença e Governança do Projeto

## 1. Identificação

**Projeto:** Plataforma Web de Avaliação Portage (IPO)  
**Licença do software:** GNU Affero General Public License v3.0 (AGPL-3.0)  
**Status:** Decisão aprovada para implementação  
**Data da decisão:** 16/09/2026

## 2. Licença do software

O código-fonte desenvolvido especificamente para este projeto será distribuído sob a **GNU Affero General Public License v3.0 (AGPL-3.0)**, salvo componentes de terceiros que estejam sujeitos a licenças próprias.

A licença do projeto deverá ser disponibilizada no arquivo `LICENSE` na raiz do repositório.

## 3. Objetivos da licença

O projeto pretende manter o software aberto para:

- estudo;
- uso;
- modificação;
- distribuição;
- colaboração da comunidade;
- criação de versões modificadas, respeitando as condições da AGPL-3.0.

A adoção da AGPL-3.0 também tem como objetivo preservar a abertura do código quando uma versão modificada do software for disponibilizada como serviço de rede, de acordo com as obrigações da licença.

## 4. Gratuidade da plataforma

A política do projeto é buscar uma **plataforma oficial de uso gratuito para o usuário final**, sempre que isso for compatível com os custos de infraestrutura e manutenção.

Gratuidade de uso não significa promessa de infraestrutura permanentemente sem custos.

O projeto deverá manter transparência sobre custos necessários para operação, hospedagem, armazenamento, e-mail, domínio, monitoramento ou outros serviços de terceiros.

## 5. Comércio e prestação de serviços

A licença AGPL-3.0 não será usada para proibir comercialização do software.

Podem existir atividades comerciais legítimas relacionadas ao projeto, incluindo, conforme a licença e as regras de governança:

- hospedagem;
- implantação;
- configuração;
- suporte;
- manutenção;
- treinamento;
- consultoria;
- desenvolvimento sob demanda;
- serviços profissionais.

O software, seus serviços oficiais e serviços de terceiros deverão ser apresentados de forma transparente e sem confundir licença do código com custo de operação.

## 6. Conteúdo do Portage/IPO

O conteúdo do instrumento será tratado separadamente do código-fonte.

A equipe do projeto registrará:

- fonte do material;
- versão utilizada;
- titularidade;
- condições de reprodução;
- condições de uso digital;
- condições de redistribuição;
- eventuais restrições.

Conforme a informação fornecida pelo responsável pelo projeto, o manual possui direitos autorais, enquanto a aplicação do inventário e as fichas do inventário são consideradas de livre replicação. Essa informação deverá ser mantida como premissa do projeto até a validação documental das condições específicas aplicáveis à versão utilizada.

O projeto não deverá incluir no repositório qualquer material cuja redistribuição não esteja documentada como autorizada.

## 7. Separação entre código e conteúdo

Quando necessário, o projeto deverá manter separadas:

1. a licença do software;
2. a documentação técnica;
3. o conteúdo do protocolo;
4. materiais de terceiros;
5. marcas, nomes comerciais e identidade visual.

A licença do software não será interpretada automaticamente como licença de todo o conteúdo incorporado à aplicação.

## 8. Contribuições

Contribuições da comunidade deverão ser realizadas preferencialmente por Pull Request.

Cada contribuição deverá:

- respeitar as licenças aplicáveis;
- não conter dados pessoais reais;
- não conter dados clínicos reais;
- não conter senhas ou chaves privadas;
- incluir testes quando pertinente;
- preservar os controles de segurança;
- documentar alterações relevantes.

## 9. Dados reais

É proibido inserir em:

- commits;
- Issues;
- Pull Requests;
- exemplos;
- fixtures;
- testes;
- screenshots;
- documentação pública

qualquer dado real de paciente, criança, responsável ou profissional que permita identificação indevida.

Os exemplos públicos deverão utilizar dados fictícios.

## 10. Segurança do repositório

O projeto deverá possuir, no mínimo:

- `README.md`;
- `LICENSE`;
- `CONTRIBUTING.md`;
- `SECURITY.md`;
- `CODE_OF_CONDUCT.md`;
- proteção da branch principal;
- revisão de Pull Requests;
- CI automatizada;
- verificação de dependências;
- controle de segredos.

## 11. Governança

Decisões críticas deverão ser documentadas em `docs/architecture/DECISOES.md`.

Mudanças relacionadas a:

- segurança;
- LGPD;
- protocolo;
- autenticação;
- autorização;
- armazenamento;
- IA;
- licença

deverão passar por revisão antes de chegar à versão de produção.

## 12. Decisão registrada

### Decisões aprovadas

- Software: **AGPL-3.0**
- Código: público/open source
- Objetivo econômico: buscar uso gratuito da plataforma oficial
- Comercialização do software: não proibida pela licença
- Conteúdo Portage/IPO: tratado separadamente do software
